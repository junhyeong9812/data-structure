# 34. 의존성 해석기

`npm install` 이 무엇을 먼저 받을지 정하는 일입니다. 위상 정렬입니다.

같은 문제를 두 알고리즘으로 풉니다. **답이 다르고, 둘 다 맞습니다.**

```
칸 알고리즘   앞에 아무것도 없는 것부터 뽑는다
DFS          다 내려갔다 돌아오는 순서를 뒤집는다
```

## 이 박스는 검증 방법이 문제입니다

32번은 전수 조사와 답을 맞대봤고, 33번은 두 파일 시스템의 상태를 맞대봤습니다.
**여기서는 그게 안 됩니다.** a와 b가 서로 상관없으면 어느 쪽을 먼저 해도 맞기 때문입니다.

그래서 **답을 비교하는 대신 성질을 검사합니다.**

```
1. 모든 노드가 정확히 한 번씩 있다
2. 앞에 와야 하는 것이 실제로 앞에 있다
3. 없는 이름이 섞이지 않았다
```

2번만 보면 안 됩니다. **노드를 통째로 빠뜨린 구현이 통과합니다.** 빠진 것은 순서를 안 어깁니다.

## 답은 같은데 실패했을 때가 다릅니다

노드 104개 중 셋이 서로 물려 있을 때:

```
칸    "순환이 있다. 경로는 이 구현이 알려주지 못한다"
DFS   "순환이 있다: a -> b -> c -> a"
```

칸 알고리즘은 "진입 차수가 0이 안 되는 것들이 남았다"까지만 압니다. 남은 것 전부가
고리는 아닙니다. DFS는 "지금 내려온 길 위에서 다시 만났다"로 잡으므로 그 길이 곧 고리입니다.

**두 알고리즘의 차이가 답이 아니라 진단 능력에 있습니다.**
그리고 진단 능력은 정상 동작 테스트로는 전혀 드러나지 않습니다.

## 층: 코어를 늘려도 못 줄이는 시간

노드 100개를 모양만 바꿔가며 세워봅니다.

| 모양 | 층 |
|---|---|
| 사슬 | **100** |
| 이진 트리 | 7 |
| 전부 독립 | **1** |

층 수가 곧 걸리는 시간입니다. 코어가 100개여도 사슬은 100 단위 시간입니다.

독립 200개에 길이 31짜리 사슬 하나를 붙이면 **0층에 201개가 몰리는데 전체는 31층**입니다.
노드의 87%가 첫 층인데 시간은 가장 긴 사슬이 정합니다.
25번 30번의 "평균이 아니라 최악이 정한다"와 같은 자리입니다.

## 특히 생각해볼 것

**1. 화살표 방향을 헷갈려도 순환 탐지는 멀쩡합니다.** 순환은 뒤집어도 순환이니까요.
그래서 "순환 테스트가 통과하니 그래프는 맞다"가 성립하지 않습니다.
방향을 뒤집으면 답이 정확히 거꾸로 나오는데, 예외가 아니라 조용한 오답입니다.

**2. DFS 의 색이 왜 둘이 아니라 셋인지가 이 구현의 전부입니다.** 함정이 넷 있고,
그중 하나는 답이 맞은 채로 시간만 2의 거듭제곱으로 터지는 종류입니다.
계약 테스트로는 안 잡히고 방문 수를 세는 측정만 잡습니다.

**3. 순환이면 부분 결과를 주지 않습니다.** 절반만 설치된 상태가 아무것도 안 한 상태보다
나쁘기 때문입니다. 짧은 목록을 조용히 돌려주는 구현이 가장 위험합니다.

**4. 답이 여럿인 문제를 재현 가능하게 만들려면 규칙을 하나 더 얹어야 합니다.**
칸 알고리즘은 우선순위 큐로 사전순 최소 하나를 고정합니다. 그래서 `TreeMap`/`TreeSet` 이
취향이 아니라 계약입니다. 05번의 "해시 순회 순서에 기대지 마라"가 여기서는 재현성 문제입니다.

**5. 층을 잘못 나눠도 펼쳐놓고 보면 순서는 맞습니다.** 층 안의 관계를 따로 봐야 잡힙니다.

**6. 변종 10개를 심어 전부 잡혔습니다.** 다만 "돌아올 때 경로에서 자기를 안 뺀다"는
처음에 살아남았습니다. 이미 끝난 가지가 고리 보고에 섞이는데, 그 상황을 만들려면
**고리로 내려가는 길에 먼저 끝나는 가지**가 있어야 합니다. 그 그래프를 따로 만들어 넣었습니다.
