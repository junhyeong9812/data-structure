# 31. 일관된 해싱

05번 해시맵은 `hash(key) % N` 으로 자리를 정했습니다. 맵 안에서는 그게 맞습니다.
같은 식을 **서버 목록**에 쓰면, 서버 한 대가 죽는 순간 거의 전부가 자리를 옮깁니다.

```
키 10만, 서버 10대. 한 대가 죽었다.

  hash % N          89,905 개가 옮겨간다   (89.9%)
  일관된 해싱        12,044 개가 옮겨간다   (12.0%)
```

옮겨간다는 것은 캐시가 비고, 데이터를 다시 끌어오고, 그 사이 원본이 다 맞는다는 뜻입니다.
서버 한 대가 죽었는데 열 대가 전부 무너지는 이유가 이것입니다.

## 차이는 N 이 식에 있느냐입니다

`hash(key) % N` 은 **N 이 식 안에 들어 있습니다.** N 이 바뀌면 모든 키의 계산이 바뀝니다.

일관된 해싱은 노드와 키를 같은 원 위에 올리고, 키는 시계 방향으로 만나는 첫 노드가 맡습니다.
배정 규칙에 N 이 없습니다. **자리들의 배치만 있습니다.**

```
원 (0 부터 2^32)

   [A]------키k------>[B]--------[C]-----
                       ^
                       k 는 B 가 맡는다. B 가 죽으면 C 로 밀린다.
                       A 와 C 사이의 키는 아무 일도 없다.
```

"다음에 오는 자리를 찾는다" 는 06번 이진 탐색 트리의 `ceilingKey` 입니다.
여기서는 `TreeMap` 을 그대로 씁니다. **원이라는 것은 마지막에서 처음으로 돌아온다는 규칙 한 줄뿐입니다.**

## 네 가지를 만들고 나란히 잽니다

| | 자리 메모리 | 한 대 죽을 때 이동 | 가중치 | 가운데 제거 |
|---|---|---|---|---|
| `ModuloSharding` | 이름 목록만 | **89,905** | 안 된다 | 된다 |
| `ConsistentHashRing` | 노드당 v 개 | **12,044** (v=100) | - | 된다 |
| `WeightedConsistentHashRing` | 무게에 비례 | - | **된다** | 된다 |
| `JumpConsistentHash` | **0** | 9,827 | 안 된다 | **안 된다** |

마지막 열이 이 표에서 제일 중요합니다. 뒤에서 다시 나옵니다.

## 특히 생각해볼 것

**1. "이동량이 적다" 가 아니라 "그것뿐이다" 입니다.**
옮겨간 키의 집합이 **죽은 노드가 맡던 키의 집합과 정확히 같습니다.** 등식입니다.
모듈로는 node-9 가 맡던 9,996 개 때문에 89,941 개를 움직입니다. 나머지 8만은 이유 없는 이동입니다.

**2. 자리를 하나만 주면 안 됩니다.** 노드 10개를 원에 한 번씩만 찍으면
제일 많이 받는 노드가 제일 적게 받는 노드의 **18배** 를 받습니다 (873 대 15,835).
자리를 여러 개 찍는 것이 가상 노드이고, 100개에서 12,044 대 8,136, 500개에서 1.11 배까지 좁혀집니다.

**3. 그런데 계속 좋아지지는 않습니다.** 1,000개에서 500개보다 **나빠집니다.**
테스트가 그 지점을 그대로 적어둡니다. 대가는 메모리입니다. 500개면 `TreeMap` 항목이 5,000 개입니다.

**4. 해시가 나쁘면 원도 나쁩니다.** `node-0` 부터 `node-9` 까지 이름 한 글자 차이가
원 위에서 **961** 만큼의 차이가 되어, 열 대가 원 전체의 50만분의 1 안에 뭉칩니다.
그러면 **node-0 이 키를 전부 가져가고 아홉 대가 놉니다.** 가상 노드를 500개 줘도 안 살아납니다.
05번에서 본 것과 같은 자리입니다. 뭉친 것을 흩는 것은 자리 수가 아니라 섞는 해시입니다.

**5. 점프 해시는 메모리가 0 인데, 대신 못 하는 것이 있습니다.**
자료구조가 없습니다. 정수 연산 몇 줄이 전부이고 이동량도 제일 적습니다.
**그런데 가운데 노드를 뺄 수 없습니다.** 번호가 0부터 N-1 로 이어져야 하기 때문입니다.

목록을 밀어서 흉내내면 뒤쪽 번호가 전부 당겨지고 **28.7%** 가 움직입니다. 1/N 보장이 사라집니다.
`UnsupportedOperationException` 을 던지게 둔 이유입니다. 조용히 틀린 답을 주는 것보다 낫습니다.

**6. 무게가 비율대로 정확히 맞지는 않습니다.** 자리를 무작위로 찍는 이상 오차가 남습니다.
`BalanceTest` 가 그 오차를 5% 넘는다고 못 박습니다. 없는 척하지 않습니다.
