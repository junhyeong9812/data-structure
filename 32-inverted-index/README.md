# 32. 역색인

문서 2,000개에서 "t199" 가 든 문서를 찾습니다.

```
전수 조사   문서를 2,000개 다 열어본다
역색인      문서를 2개 열어본다
```

`2` 대 `2,000` 입니다. 이 차이가 이 박스의 전부입니다.

## 색인의 방향을 뒤집습니다

```
정방향   문서 -> 그 안의 항들        문서를 보여줄 때 쓴다
역색인   항 -> 그 항이 있는 문서들   찾을 때 쓴다

  "고양이" -> [문서 3, 문서 9, 문서 41]
  "검은"   -> [문서 9, 문서 41, 문서 77]
             ------------------------
  둘 다 있는 문서 = [9, 41]
```

포스팅 리스트를 **문서 번호 오름차순으로 유지하는 것**이 이 구조의 값을 만듭니다.
정렬돼 있으면 교집합을 한 번 훑기로 냅니다. 안 돼 있으면 한쪽마다 상대를 다 뒤져야 합니다.

06번 이진 탐색 트리에서 "정렬이 곧 능력" 이라고 했던 것이 여기서 다시 나옵니다.

## 이 박스가 다른 이유: 검증 방법이 문제입니다

교집합 병합은 부등호 하나만 틀려도 **"봐야 하는 문서를 안 본다"** 가 됩니다.
예외가 안 납니다. 결과가 조용히 몇 개 빠질 뿐입니다.

그래서 **답이 맞는 구현을 두 개 만듭니다.**

| | 색인 | 넣기 | 찾기 | 이 구현의 역할 |
|---|---|---|---|---|
| `LinearScanEngine` | 없다 | O(1) | O(문서 수) | **기준선.** 쉬워서 맞다 |
| `InvertedIndexEngine` | 크다 | O(항 수) | O(포스팅) | 본체. 빨라서 의심스럽다 |

두 엔진에 같은 질의를 넣고 **문서 번호도 점수도 같은지** 봅니다.
`CrossCheckTest` 가 문서 2,000개에 질의 250개를 무작위로 넣습니다.

23번 스플레이 트리에서 배운 것이 여기 그대로 있습니다.
**계약 테스트를 다 통과해도 틀린 구현이 있습니다.** 거기서는 회전 수가 잡았고, 여기서는 대조가 잡습니다.

## 특히 생각해볼 것

**1. 답이 같은데 일하는 양이 다른 선택이 있습니다.** AND 질의에서 어느 포스팅 리스트부터
병합하느냐입니다. 짧은 것부터 하면 비교 **231**, 질의에 적힌 순서대로 하면 **683** 입니다.

답이 같으니 `CrossCheckTest` 로는 **절대 안 잡힙니다.** `MeasurementTest` 만 잡습니다.
12번 스킵 리스트의 "답이 맞는데 느린 구현" 과 같은 자리입니다.

**2. 색인과 질의에 다른 분석기를 주면 조용히 0건이 나옵니다.**
한쪽만 소문자로 내리거나 한쪽만 불용어를 지우면, 예외도 경고도 없이 결과가 빕니다.
`AnalyzerMismatchTest` 가 이 경우만 따로 봅니다. **전수 조사에도 똑같이 일어납니다.**
색인의 버그가 아니라 파이프라인의 버그라서, 구조를 바꿔도 안 없어집니다.

**3. 위치를 담는 대가가 색인의 대부분입니다.**
문서 2,000개에서 포스팅이 37,348개인데 위치 정수는 **40,158개** 입니다.
원문의 토큰 하나마다 정수 하나입니다. 위치를 버리면 색인이 작아지고 **구문 검색을 아예 못 합니다.**

전수 조사는 원문을 들고 있으니 위치가 공짜입니다. 다시 분석하면 순서가 그대로 나옵니다.
**색인은 원문을 버렸기 때문에 미리 담아두지 않으면 영영 못 합니다.**

**4. 구문 질의는 AND 보다 좁습니다.** "검은 고양이" 를 AND 로 물으면 둘 다 든 문서가 전부 나오는데,
구문으로 물으면 **붙어 있는** 것만 나옵니다. 순서를 뒤집으면 답이 사라집니다.
그래서 먼저 AND 로 좁히고 그 안에서만 위치를 봅니다. 안 좁히면 전수 조사가 됩니다.

**5. 한계 - 모든 문서에 있는 항을 물으면 색인이 집니다.**
포스팅 리스트 길이가 문서 수와 같아지므로 방문이 **500개 문서에 500** 입니다.
25번의 "모든 점이 같은 거리", 30번의 "결과가 크면 진다" 와 같은 자리입니다.
색인은 후보를 줄여야 이기는데, **줄일 것이 없으면 줄일 수 없습니다.**

**6. df 가 N 이면 점수가 0 입니다.** 버그가 아니라 TF-IDF 의 뜻입니다.
모든 문서에 있는 말은 문서를 가르지 못합니다. 문서가 하나뿐인 색인에서는 모든 점수가 0 이고
순위가 문서 번호 순으로 무너집니다. 테스트가 그 경우를 그대로 적어둡니다.

**7. 점수를 더하는 순서에 함정이 있습니다.** 병합 순서로 더하면 값이 거의 같은데
`double` 오차가 다르게 쌓여 전수 조사와 **마지막 자리에서 갈립니다.**
그러면 정답인데도 대조가 실패합니다. 이 박스의 주력 검증이 무너지는 유일한 경로입니다.
