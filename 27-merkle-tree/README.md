# 27. 머클 트리

01번부터 26번까지의 자료구조는 전부 **"무엇이 들어 있나"**에 답했습니다.
머클 트리는 다른 질문에 답합니다. **"이게 그대로인가."**

블록 100만 개짜리 파일이 상대에게도 있습니다. 전부 보내 비교하면 되지만 그건 파일을 한 번 더 옮기는 것입니다.
**해시 하나로 요약하면** 같은지는 알 수 있는데 **다를 때 어디가 다른지를 모릅니다.**

머클 트리는 잎에 블록 해시를 두고 **위로 올라가며 둘씩 합쳐 해시**합니다.
뿌리 하나가 전체를 요약하고, 다르면 트리를 내려가며 **O(log n)** 만에 어느 블록인지 찾습니다.
같은 부분트리는 해시 한 번 비교로 통째로 건너뜁니다.

## 더 중요한 것은 포함 증명입니다

"3번 블록이 이 파일에 들어 있다"를 증명하는 데 파일이 필요 없습니다.
경로의 형제 해시 log n 개면 되고, 100만 블록이면 **해시 20개(SHA-256 으로 640바이트)** 입니다
(`oneMillionLeaves` 가 그 20을 잽니다).

11번 블룸 필터는 **정확성을 팔아 메모리를 샀습니다.** 여기서는 아무것도 팔지 않습니다.
해시 충돌이 없다는 가정 위에서 **증명은 확정적입니다.** 그 가정이 조건문이라는 것도 같이 봅니다.

| | 해시 하나 | 머클 트리 |
|---|---|---|
| 같은지 안다 | 된다 | 된다 |
| 어디가 다른지 | **모른다** | O(log n) |
| 블록 하나만 증명 | 파일 전체가 필요하다 | **해시 log n 개** |
| 블록 하나 갱신 | 전부 다시 해시 | **경로만** (1024잎에서 2047번 -> 11번) |

실무: git 의 커밋/트리 객체, IPFS, 비트코인과 이더리움, 인증서 투명성 로그(CT),
카산드라의 anti-entropy 복구, 그리고 rsync 의 델타 전송.

## 잎이 2의 거듭제곱이 아닐 때 (반드시 정해야 합니다)

이 문제집은 **짝 없는 마지막 노드를 그대로 올립니다**(승격). 흔한 다른 방법은
마지막을 자기 자신과 짝지어 해시하는 것인데(비트코인), 그쪽에는 **CVE-2012-2459** 가 있습니다.
`OddLeafCountTest` 가 두 규칙을 나란히 계산해 그 자리를 못 박습니다.
**잎이 2의 거듭제곱이면 두 규칙의 값이 같습니다.** 8블록으로만 테스트하면 이 취약점이 안 보입니다.

## 하는 방법

```
MerkleTreeTest 를 따라친다 -> PrefixedHashing 2개 -> MerkleTree 4개 -> MerkleProof 1개 -> MerkleProblems 2개
```

```bash
cd ~/project/myway/data-structure && ./run.sh 27      # 79개 중 75개가 실패한다
```

## 특히 생각해볼 것

**1. 접두사 한 바이트가 위조를 막습니다.** 두 번째 원상 공격(second preimage)이고,
`SecondPreimageTest` 가 그 위조를 **실제로 성공시킵니다.** 이 문제집에서 값이 제일 나가는 테스트입니다.
조건은 "접두사를 붙였나"가 아니라 **"잎과 내부에 서로 다른 값을 붙였나"** 입니다. 변종으로 확인했습니다.
잎 접두사만 지우면 두 공간이 아직 갈라져 있어 안 되고, **둘을 같은 값으로 만드는 순간** 성립합니다.

**2. 잎 하나가 바뀌면 뿌리가 바뀌고, 바뀌는 것은 경로뿐입니다.** 1024잎에서 새 값은
**11개**, 나머지 2036개는 원본 배열을 **같은 객체로** 가리킵니다.
26번 영속 자료구조의 경로 복사와 같은 발상입니다.

**3. 걸음 수를 안 세면 정답과 오답이 구별되지 않습니다.** 이 문제의 핵심 함정입니다.
1024블록에 차이 1개면 `findFirstDifference` 가 비교 **11번**, 차이 3개면 `diffBlocks` 가 **55번**입니다
(전수는 둘 다 1024번). `diffBlocks` 에서 "같으면 건너뛴다"를 빼면 **답이 똑같이 맞고**
79개 중 76개가 통과합니다. 갈리는 것은 **횟수를 세는 테스트 셋뿐**입니다.

**4. 증명은 뿌리가 맞다는 것만 보입니다.** 그 뿌리가 진짜인지는 이 물건 밖의 문제입니다.
실무가 뿌리를 서명해 배포하는 이유입니다.

## 한계 (고칠 수 없는 성질)

**1. 해시가 무너지면 전부 무너집니다.** `ToyHash` 로 충돌을 만들면 서로 다른 파일이 같은 뿌리를 갖고,
`findFirstDifference` 가 **-1(같다)** 을 답하고, 없는 블록의 증명이 통과합니다.
전수 비교는 같은 자리에서 정확히 답합니다. **"확정적"은 무조건이 아니라 조건부입니다.**

**2. 대부분 다르면 집니다.** 64블록이 전부 다르면 노드 127개를 다 봅니다. 전수 비교는 64번입니다.
머클 트리가 이기는 것은 **"대부분 같다"** 일 때뿐입니다.

**3. 블록을 끼워 넣거나 빼면 다시 지어야 합니다.** 그 뒤 모든 잎의 자리가 밀립니다.

**4. 승격은 증명 길이를 흘립니다.** 잎 3개짜리 트리에서 2번 잎의 증명만 한 걸음이라, 길이만 봐도 압니다.

**5. `verifyBatch` 는 빈 목록에 true 를 줍니다.** "전부 통과했다"와 "검증할 것이 없었다"가
같은 값입니다. 부르는 쪽이 개수를 따로 봐야 하고, 자료구조가 대신 정해줄 수 없습니다.

**6. 테스트가 약했던 자리가 하나 있었습니다.** `verify` 가 뿌리의 **앞 4바이트만** 비교해도
위조 테스트 일곱 개를 포함해 79개가 다 통과했습니다. 뿌리의 바이트를 하나씩 뒤집는
`everyByteOfTheRootMatters` 를 뒤늦게 넣었습니다. **검증은 전부 보거나 안 보거나 둘 중 하나입니다.**
