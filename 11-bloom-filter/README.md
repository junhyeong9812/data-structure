# 11. 블룸 필터 (세 가지 구현)

01~10에서 만든 것들은 전부 **정확했습니다.** 있으면 있다고 하고 없으면 없다고 했습니다.
여기서는 그 정확성을 **일부러 팝니다.** 대가로 메모리를 수십 배 줄입니다.

거래의 모양이 비대칭이라는 점이 전부입니다.

```
mightContain 이 false  ->  확실히 없다.   오답이 아예 불가능하다
mightContain 이 true   ->  아마 있다.     없는데 있다고 할 수 있다
```

"없다"가 확실하니까 **비싼 조회를 건너뛰는 앞단 필터**로 쓸 수 있습니다.
false면 디스크를 안 읽고, true면 읽어서 확인합니다. 틀려도 한 번 더 읽을 뿐 답이 틀리지 않습니다.

(카산드라/HBase의 SSTable 조회, 크롬의 악성 URL 목록, CDN의 "한 번만 요청된 것은 캐시 안 함"이
전부 이 모양입니다.) 10번에서 **일부러 잊어서** 한정했다면, 여기서는 **일부러 헷갈려서** 한정합니다.

| | HashSet | 블룸 필터 |
|---|---|---|
| 100만 개 저장 | 수십 MB (원소 자체를 담는다) | **1.2MB** (1% 오탐) |
| 원소를 꺼내기 | 된다 | **안 된다** - 담은 적이 없다 |
| 삭제 | 된다 | **안 된다** (Counting이 푼다) |
| 오답 | 없다 | 오탐만. 누락은 없다 |

## 크기는 감으로 정하지 않습니다

```
비트 수     m = -n ln(p) / (ln2)^2
해시 개수   k = (m/n) ln2
```

**1% 오탐이면 원소당 9.586비트, 해시 7개입니다.**
원소가 int든 100자 URL이든 9.586비트입니다. **이 "원소 크기와 무관"이 이기는 지점입니다.**

k를 늘리면 좋을 것 같지만 아닙니다. 너무 많으면 비트가 빨리 차서 오히려 오탐이 늡니다.
위 공식의 k가 정확히 그 골짜기입니다.

## 특히 생각해볼 것

**1. 해시 함수를 k개 만들 필요가 없습니다.** 64비트 해시 하나를 반으로 갈라 쓰면
이론상 같은 성능이 나옵니다(이중 해싱 - Kirsch & Mitzenmacher, 2006).
함정이 셋이고, 그중 하나는 05번 음수 해시와 같은 함정입니다.

셋 중 `h2`가 0인 경우는 **이 설계에서는 어떤 테스트로도 못 잡습니다.**
그래도 남깁니다. 해시 함수를 바꾸는 순간 살아나는 방어선입니다.

**그런데 19번에서는 같은 방어선을 잡습니다.** 거기서는 해시가 seed를 주입받아
입력이 (원소, seed) 쌍이 되고, 그러면 걸리는 짝을 실제로 구성할 수 있습니다.

**"테스트가 못 잡는다"는 코드의 성질이 아니라 설계의 성질입니다.**
같은 방어선인데 한쪽은 검증할 수 없고 한쪽은 할 수 있습니다.
무작위를 주입받게 만드는 것(12번 스킵 리스트에서 처음 나온 규칙)이
성능이나 재현성만이 아니라 **검증 가능성**까지 바꿉니다.

**2. 왜 삭제를 못 하는가.** A와 B가 3번 비트를 함께 켰는데 A를 지운다고 3번을 끄면
**B가 같이 사라집니다.** 누락이 생기고, 이 자료구조의 유일한 보장이 깨집니다.

**3. Counting이 그걸 푸는데, 값이 셋입니다.** 메모리 8배(실무는 4비트로 4배),
포화된 계수기는 **영원히 안 내려가고**, **오탐인 원소를 지우면** 누락이 생깁니다.

세 번째가 중요합니다. **삭제를 얻는 대신 "누락 없음" 보장을 잃습니다.**
`falseNegativeAppears` 테스트가 실제로 그 경우를 찾아 보여줍니다.

**4. 기본형의 진짜 약점은 오탐이 아니라 용량 고정입니다.**
100만으로 잡았는데 1000만이 들어오면 오탐률이 1%에서 90%로 뜁니다.
그때는 이미 늦었습니다. **원소를 담지 않았으니 다시 만들 수도 없습니다.**
(해시맵은 리사이즈로 다시 배치했습니다. 여기서는 배치할 원소가 없습니다.)

**5. Scalable은 늘리는 게 아니라 잇습니다.** 그런데 필터가 늘면 오탐 기회도 늘어서,
**새 필터일수록 더 엄격하게** 만듭니다.

```
필터 0: 용량 n,  오탐률 p
필터 1: 용량 2n, 오탐률 p/2
필터 2: 용량 4n, 오탐률 p/4
```

전체 오탐률은 `1 - (1-p)(1-p/2)(1-p/4)...`인데 **2p를 넘지 않습니다.** 등비급수가 수렴하니까요.
필터를 무한히 이어도 유계입니다.
