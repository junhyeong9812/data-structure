# 16. 레드블랙 트리

06번 이진 탐색 트리가 정렬 입력에서 무너진 뒤로, **같은 문제에 네 번째 답**입니다.

```
12번 스킵 리스트   동전을 던져 확률로 맞춘다.   회전이 없다
15번 B-트리        노드를 뚱뚱하게, 위로만 자란다. 회전이 없다
16번 여기          회전으로 강제로 맞춘다.       보장이다
```

왜 또 필요한가. 앞의 둘에는 각각 대가가 있었습니다.

- 스킵 리스트: 최악을 **막지 못합니다.** 확률이 낮을 뿐입니다.
- B-트리: 노드가 커서 **메모리 안에서는 낭비**입니다. 캐시 한 줄에 안 들어갑니다.

레드블랙 트리는 **메모리 안에서, 보장으로** 균형을 잡습니다.
노드는 이진 트리 그대로이고 색 비트 하나만 더 듭니다.
자바 `TreeMap`/`TreeSet`, C++ `std::map`, 리눅스 커널 스케줄러가 이것입니다.

## 지켜야 할 것 넷

```
1. 뿌리는 검다
2. 빨간 링크는 왼쪽에만          <- 좌편향(left-leaning)의 정의
3. 빨간 노드가 연달아 나오지 않는다
4. 모든 뿌리-잎 경로의 검은 링크 수가 같다
```

**4번이 균형의 정체입니다.** 검은 높이가 같으니 가장 짧은 경로(전부 검정)와
가장 긴 경로(검빨검빨...)의 길이 차이가 **두 배를 못 넘습니다.**
그래서 높이가 `2*log2(n+1)` 이하로 **보장됩니다.** 12번의 확률과 다른 점입니다.

## 15번을 먼저 푸세요

**레드블랙 트리는 B-트리를 이진 트리로 흉내낸 것입니다.**

```
빨간 링크로 이어진 두 노드  =  2-3 트리의 키 2개짜리 노드
검은 링크                    =  2-3 트리의 진짜 간선
```

이 대응이 보이면 회전과 색 뒤집기가 15번의 어느 동작인지 알아볼 수 있습니다.
`blackHeightIsTwoThreeHeight` 테스트가 그 대응을 숫자로 확인합니다.
10만 개의 검은 높이가 `log3(n)`과 `log2(n)` 사이에 들어옵니다.

2번 규칙(좌편향)이 있는 이유도 여기 있습니다. **모양의 가짓수를 줄여 경우의 수를 줄입니다.**
좌우를 다 허용하면(고전적 레드블랙 트리) 2-3-4 트리가 되고 코드가 두 배가 됩니다.

## 특히 생각해볼 것

**1. 회전은 링크만 옮기는 것이 아닙니다.** 빠뜨리면 회전이 검은 높이를 바꿔
4번이 즉시 깨집니다(26개 중 16개가 무너집니다).

**2. 새 노드를 무슨 색으로 넣느냐가 4번을 지킵니다.**
2-3 트리로 읽으면 **"기존 노드에 키를 하나 더 끼워 넣는 것"**입니다.

**3. `balance`의 세 검사는 순서가 계약입니다.** 바꾸면 불변식이 깨진 채로 위로 올라갑니다.
그리고 `else if`가 아니라 **연달아** 일어납니다.

**4. `flipColors`는 대입이 아니라 반전입니다.** 한 동작이 넣기와 지우기 양쪽에서,
그것도 **방향이 반대인 채로** 쓰이기 때문입니다. 대입으로 쓰면 지우기 쪽이 깨집니다.

**5. `put`이 반환값을 부모에 다시 대입하는 방식입니다.**
회전으로 부모가 바뀌어도 링크가 저절로 맞습니다. **부모 포인터가 필요 없는 이유입니다.**

**6. 지우기가 어려운 이유.** 검은 노드를 지우면 그 경로의 검은 높이가 줄어 4번이 깨집니다.
그래서 **내려가기 전에 미리 빨강을 확보해둡니다.**
15번 B-트리에서 "내려가기 전에 미리 채운다"고 했던 것과 정확히 같은 발상입니다.

**7. `delete`에서 key 비교를 두 번 합니다.** 그 사이에서 `h`가 다른 노드가 되기 때문입니다.
한 번만 하면 조용히 틀립니다.

**8. 정직한 기록 하나.** 지우기 시작 전 뿌리를 빨갛게 만드는 줄이 있습니다.
표준 구현의 관례인데, **그 줄을 지워도 우리 테스트가 전부 통과합니다.**
(크기 1~6 트리의 모든 삭제 순서 전수 + 무작위 3000스텝 + TreeMap 대조 2만스텝)

뿌리에서 `flipColors`가 어차피 색을 뒤집어 같은 효과를 내고 마지막에 뿌리를 검게 강제하기
때문으로 보입니다. 그래도 남깁니다. 11번 블룸 필터의 `h2 == 0`과 같은 종류입니다.
**테스트가 구별하지 못하는 코드도 있습니다.**

**9. 불변식을 테스트가 직접 검사합니다.** 계약 테스트만으로는 절대 안 잡힙니다.
색만 엉망이고 답은 맞는 구현이 얼마든지 가능하기 때문입니다.
`RedBlackTreeInvariantTest`가 넣는 내내, 지우는 내내 네 규칙을 전부 확인하고,
크기 1~6 트리에 대해서는 **모든 삭제 순서를 전수로** 돕니다.
