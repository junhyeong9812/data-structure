# 17. 펜윅 트리 (이진 인덱스 트리)

13번 세그먼트 트리는 결합법칙만 있으면 무엇이든 접었습니다. 합, 최소, 최대, GCD, 행렬 곱.
**그 일반성의 값이 코드 길이와 메모리였습니다.**

펜윅 트리는 **역연산이 있는 연산만** 합니다. 사실상 합입니다.
그 하나를 포기하면 코드가 열 줄이 되고 메모리가 4분의 1이 됩니다.

| | 세그먼트 트리 (13번) | 펜윅 트리 |
|---|---|---|
| 결합 함수 | 아무거나 (모노이드) | **역연산이 있어야 한다** |
| 최소/최대 | 된다 | **안 된다** |
| 메모리 | 4n | **n + 1** |
| 조회/갱신 | O(log n) | O(log n), 상수가 더 작다 |
| 코드 | 수십 줄 | **열 줄** |

**왜 역연산이 필요한가.** 구간 합을 이렇게 구하기 때문입니다.

```
rangeSum(l, r) = prefixSum(r) - prefixSum(l-1)
```

앞쪽을 통째로 구해놓고 **빼서** 가운데를 얻습니다.
최소값에는 이 뺄셈이 없습니다. `min(a..r)`과 `min(a..l-1)`을 안다고 `min(l..r)`을 알 수 없습니다.

**"덜 하면 더 싸다"가 이 문제집에서 계속 나옵니다.**
07번 힙(전체 정렬 대신 부분 순서), 11번 블룸 필터(정확성 대신 메모리),
14번 유니온 파인드(경로 대신 속도). 여기가 네 번째입니다.

## 트리라고 부르지만 배열 하나입니다

노드도 링크도 없습니다. **인덱스의 비트 패턴이 트리 구조를 대신합니다.**

**규칙은 하나입니다. `tree[i]`는 `i`에서 왼쪽으로 `i & -i`개를 덮습니다.**

```
i    i&-i   덮는 구간
1     1     [1..1]
2     2     [1..2]
3     1     [3..3]
4     4     [1..4]
6     2     [5..6]
8     8     [1..8]
```

`i & -i`는 **최하위 1비트**입니다. 2의 보수라 그렇습니다.

그래서 **7까지의 합이 필요하면 7 = 4 + 2 + 1로 쪼개** `tree[7]`, `tree[6]`, `tree[4]`
세 칸만 더하면 됩니다. **걸음 수가 곧 1비트의 개수**라 log n 이하입니다.

## 특히 생각해볼 것

**1. 안쪽에서 1부터 세는 이유가 있습니다.** 어기면 **무한 루프입니다.**
그래서 이 문제집은 **모든 테스트에 30초 기본 제한**이 걸려 있습니다.

**2. `add`와 `prefixSum`은 걷는 방향이 반대입니다.**
한쪽을 반대로 쓰면 정확히 1번의 그 무한 루프에 빠집니다.

**3. `set`을 직접 못 합니다.** 펜윅 트리는 **차이를 더하는 것만** 합니다.
그래서 값 바꾸기가 두 배 비쌉니다. 그것도 대가입니다.

**4. `buildFrom`은 O(n)입니다.** 하나씩 `add`하면 O(n log n)인데,
한 번만 훑고도 되는 이유가 이 구조의 성질에 있습니다.

**5. `findPrefixIndex`가 이 구조의 숨은 재주입니다.**
`prefixSum`을 부르며 이진 탐색하면 O(log^2 n)인데, **트리의 칸 구조가 이미 이진 탐색의 모양**이라
그걸 그대로 타면 O(log n)입니다.

쓰임새가 분명합니다. 값의 빈도를 세어두고 **"정렬했을 때 k번째는 무엇인가"**를 O(log n)에 답합니다.
훑어서 세면 O(n)입니다. (온라인 순위표, 중앙값 추적, 백분위 집계가 이 모양입니다.)

**6. 2차원은 1차원을 두 번 겹친 것입니다.** 루프가 이중이 될 뿐입니다.
3차원도 같은 방식으로 됩니다(O(log^3 n)). 겹칠 때 안쪽 루프에 함정이 하나 있습니다.

**7. 직사각형 합은 포함-배제로 구합니다.** 위와 왼쪽을 빼면 겹친 곳을 두 번 뺀 셈이라
한 번 되돌려주는데, **마지막 항의 부호**를 빠뜨리는 것이 여기서 제일 흔한 실수입니다.
(실무 대응물: 이미지의 적분 영상, 히트맵 집계, OLAP 큐브의 부분 합.)

**8. `BinaryIndexedTree`는 같은 것의 다른 이름입니다.**
아카이브 목록에 둘 다 있어서 적어둡니다. `FenwickTree2D`와 `BinaryIndexedTree2D`도 같습니다.
04번 `LinkedQueue`, 07번 `PriorityQueue`와 같은 처리입니다.
